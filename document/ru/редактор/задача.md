
# Задача
Миссии, которые считаются выполненными при выполнении определенных условий
- При выполнении конфигурированных условий цель считается достигнутой, и в верхней части экрана отображается сообщение.
- Они отображаются в списке миссий игрока и в списке заданий по категориям.
- Вознаграждение не выдается автоматически. Игрок получает его, когда открывает задание и нажимает на кнопку получения.
- До тех пор, пока вознаграждение не будет получено, на панели списка будет отображаться ленточка, указывающая на то, что оно еще не получено.
- Получение предметов позволяет изменять уровень категории, количество выполненных действий и количество имеющихся предметов.
- Все, что необходимо запускать в моменты, не предусмотренные условиями (например, при первом запуске или когда игра окончена), входит в конфигурацию событий основных настроек.

## Категория.
ID категории, к которой относится задача
- Укажите ID категории, к которой будет отнесена эта задача.
- После конфигурации на экране категорий игроков появится список заданий, а в списке миссий они будут отображаться сгруппированными по категориям.
- Если поле оставлено пустым, задание не будет отнесено ни к одной категории и будет отображаться в начале списка заданий.
___

## синхронизация
Момент запуска задачи (фиксированное значение `matched`)
- Задача зафиксирована в состоянии `matched` (когда выполняются конфигурированные условия) и не подлежит редактированию.
- Вознаграждение можно получить только один раз, и после его получения статус «выполнено» останется неизменным.
- Все, что необходимо запускать в другое время, конфигурируется в разделе «События» основных настроек.
- [_event_](ru/редактор/мероприятие)
___

## Начальное состояние отображения
Начальное состояние значка задачи (выполнение зависит от условий; при данной конфигурации задача не считается выполненной)
- Условия выполнения задачи определяются в разделе «Требования», а этот пункт влияет только на внешний вид значка списка.
- secreted: Не отображается в списке задач до тех пор, пока не будут выполнены все требования (само выполнение происходит в соответствии с условиями).
- hidden・hinted: на значке появляется перечеркивающая линия, и он отображается как «неразблокированный».
- released: Косая черта исчезнет, и элемент будет отображаться как «освобожденный».
- Завершённые задачи не исчезают из списка. Если задача снова становится незавершённой, это обозначается перечёркнутым значком «Назад».
___

## правила и условия
Условия выполнения задачи
- Условия выполнения задачи.
- Если вы выполните это условие, задача будет считаться выполненной, и вы сможете получить вознаграждение.
- Если вы перестанете соответствовать условиям до получения вознаграждения, статус вернётся к «Назад», и вы не сможете его получить. Вы сможете получить вознаграждение, если вновь выполните условия.
- Задачи, для которых не установлены условия, не будут выполнены.
___

### Тип.
Тип элемента, на который ссылается условие.

|Тип.|Значения, на которые ссылаются|
|-|-|
|Категория.|Категория на уровне.|
|Действие.|Количество раз, когда действие было выполнено.|
|предмет|Количество удерживаемых предметов.|
___

### ID элемента
ID элемента, на который ссылается условие.
___

### значение
Необходимые для выполнения требований значения.
- Условие выполняется, если значение выше или равно указанному значению.
___

### Вероятность потребления [0-1].
Вероятность того, что предмет будет потреблен (0-1, действительно только если тип - Предмет).
- Вероятность того, что предмет будет потреблен при выполнении условия и действия.
- Всегда расходуется при `1`, с вероятностью 50% расходуется при `0,5` и не расходуется при `0`.
- Значение по умолчанию - `1` (всегда потребляется).
- Неверно, если тип не является предметом.
___

### снаряжение
Требуется, чтобы предмет находился в состоянии снаряжения (только если тип - Предмет) или
- При включении этого параметра необходимо не только снаряжение, но и владение предметом.
- Неверно, если тип не является предметом.
___

## вознаграждение
Конфигурация вознаграждения за выполнение задачи
- Это вознаграждение, которое можно получить, открыв выполненное задание и нажав на полоску получения.
- Вы можете изменять уровень категории, количество выполнений действия и количество предметов в инвентаре.
- Также можно указать количество с минусом.
- Для задач, для которых не установлено вознаграждение, индикатор получения не отображается, и они считаются завершенными по факту выполнения.
___

### Тип.
Тип приобретаемого элемента.

|Тип.|Что получено.|
|-|-|
|Категория.|Уровень (добавлено преобразование опыта)|
|Действие.|Количество выполненных операций.|
|предмет|количество имущества|
___

### ID элемента
ID, идентифицирующий приобретаемый элемент.
___

### значение
Значения должны быть получены.
- Минусы уменьшают количество владений, количество раз их выполнения и их уровень. Однако оно не может быть ниже 0.
- Если у Предмета есть максимальное количество владений (макс.), то количество собственных владений не будет увеличиваться сверх этого значения.
- Если тип - категория, значение конфигурации добавляется непосредственно к уровню (1 - 1 уровень, 0,5 - 0,5 уровня). Обычный способ настроить это - конфигурация опыта действия. Эта конфигурация не нужна, если нет ничего особенного.
___

### Вероятность [-1…1]
Вероятность успеха получения (отрицательные значения оцениваются только в случае неудачи)
- Установите конфигурацию вероятности получения в виде десятичного числа от -1 до 1. При определении вероятности используется абсолютное значение.
- Если значение положительное, оценка производится только в случае успеха при выполнении действия: при значении `1` предмет получается обязательно, а при значении `0.5` — с вероятностью 50 %.
- Если значение отрицательное, оценка производится только в случае неудачи действия: при значении `-1` предмет обязательно получается, а при значении `-0.5` — с вероятностью 50 %.
- При значении `0` он не получается ни в случае успеха, ни в случае неудачи.
- Значение по умолчанию — `1` (обязательно получается в случае успеха).
___

## целевая группа
Группировка задач по категориям
- Примените одну из конфигураций групп в разделе Basic.
- Список задач отображается в порядке, определенном для конфигурации групп.
- Внутри категории они отображаются с дальнейшим разделением на группы.
- Если оставить пустым, то группировка не производится.
